# Walkthrough: Running TPGMM on the `dual_ur10` Branch

This guide provides a comprehensive walkthrough for setting up and running the Task-Parameterized Gaussian Mixture Model (TPGMM) package specifically for the `dual_ur10` setup.

## 1. Environment Setup

### Prerequisites
- **ROS**: Recommended ROS Noetic or Melodic.
- **Python**: Python 3.8+ is recommended.
- **MoveIt**: Ensure MoveIt is installed for trajectory planning and visualization.

### Dependencies
Install the required Python packages:
```bash
pip install numpy matplotlib scipy papermill nbclient nbformat dtw-python
```
*Note: A conda environment named `lfd` is suggested in the original notes.*

## 2. Launching the Package

To start the necessary ROS nodes, use the `lfd.launch` file. This launch file initializes the TPGMM nodes, RViz converters, and MoveIt interfaces for both UR10 robots (`ur10_1` and `ur10_2`).

```bash
roslaunch tp_gmm lfd.launch task:='pick'
```

### Passable Parameters to `lfd.launch`
- `task`: (default: `Rbolts`) The name of the task. This should correspond to a task directory in `data/` and `tasks/`. Examples: `pick`, `place_ur10_1`, `place_ur10_2`.
- `subtask`: (default: `action`) The name of the subtask.

## 3. Training the TPGMM Model

Before you can reproduce trajectories, you must train the model for a specific task. This is done via the `StartTPGMM_service`.

### Training via Service Call
For `ur10_1`:
```bash
rosservice call /ur10_1/StartTPGMM_service "task_name: 'pick'"
```

For `ur10_2`:
```bash
rosservice call /ur10_2/StartTPGMM_service "task_name: 'pick'"
```

**What happens during training:**
1. The node executes the `demons_to_samples_ur10_demons.ipynb` notebook using `papermill`.
2. It processes raw demonstration data (txt files in `data/<task_name>/`) into TPGMM samples.
3. It fits the GMM model and saves it as `tasks/<task_name>/TPGMM_model.pkl`.

## 4. Reproducing Trajectories

Once the model is trained, you can generate new trajectories by providing start and goal poses.

### Reproduction via Service Call
```bash
rosservice call /ur10_1/ReproduceTPGMM_service "task_name: 'pick'
frame_id: 'ur10_1_base_link'
start_pose:
  header:
    frame_id: 'ur10_1_base_link'
  pose:
    position: {x: 0.5, y: -0.2, z: 0.5}
    orientation: {x: 0.0, y: 0.707, z: 0.0, w: 0.707}
goal_pose:
  header:
    frame_id: 'ur10_1_base_link'
  pose:
    position: {x: 0.6, y: 0.2, z: 0.1}
    orientation: {x: 0.0, y: 0.707, z: 0.0, w: 0.707}"
```

### Parameters for `ReproduceTPGMM_service`
- `task_name`: The name of the task to use for reproduction.
- `frame_id`: The reference frame for the poses.
- `start_pose`: The desired starting pose (`geometry_msgs/PoseStamped`).
- `goal_pose`: The desired goal pose (`geometry_msgs/PoseStamped`).

## 5. Automated Experiments

You can use the `experiments_handler.py` script to automate multiple reproductions with randomized poses.

```bash
rosrun tp_gmm experiments_handler.py
```
*Note: Ensure `task_param` and `subtask_param` are set (usually via `lfd.launch`) before running this script.*

## 6. Visualization in RViz

The package publishes several topics for visualization:
- `/ur10_1/gmm/cartesian_space`: Visualizes the GMM Gaussians in Cartesian space.
- `/ur10_1/gmm/regressed_trajectory`: The generated trajectory after regression.
- `/ur10_1/solid_primitives_viz`: Visualization of the search space constraints for MoveIt.

## 7. Data Collection (Optional)

If you need to record new demonstrations:
1. Run your robot simulation or connect to the real robot.
2. Use `scripts/collect_trajectories_data.py` to move the robot and save trajectories into rosbags.
3. The rosbags should be placed in the directory expected by the `demons_to_samples` notebooks.
